01AGENTS.md / CLAUDE.md🩹 Patchy
PaperClaw/CLAUDE.md exists but is host-specific (C:\Users\INS-29\.dotnet\dotnet.exe, C:\DEV\PaperClaw\…) and PowerShell-only. No architecture overview, no test invocation, no conventions, no project layout. A fresh agent on macOS/Linux is dead on arrival.
Fix: rewrite as portable commands (dotnet build, dotnet test) at repo root, add a section on the double-nested PaperClaw/PaperClaw/ layout, list the abstractions, and link the search slash command.
02Strict compiler settings🩹 Patchy
PaperClaw.csproj:7 has <Nullable>enable</Nullable> — good. But no <TreatWarningsAsErrors>, no <AnalysisLevel>latest-recommended</AnalysisLevel>, no <EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>, and no Directory.Build.props applying these to all projects.
Fix: add a root Directory.Build.props with <TreatWarningsAsErrors>true</TreatWarningsAsErrors>, <AnalysisLevel>latest-recommended</AnalysisLevel>, <EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>.
03Strict linter / formatter💀 Broken
No .editorconfig, no analyzer packages (no Microsoft.CodeAnalysis.NetAnalyzers, no StyleCop.Analyzers, no Roslynator), no dotnet format enforcement anywhere.
Fix: drop a strict .editorconfig (severity: error on style rules), add StyleCop.Analyzers via Directory.Build.props, and require dotnet format --verify-no-changes in CI.
04Schema validation at boundaries👍 Solid
Claude tool surface uses explicit JSON Schemas (ClaudeSearchService.cs:13-24). Config is validated by null-throw (Program.cs:16-21). Internal types are nullable-checked. There is no external HTTP API surface — the only inputs are file paths and CLI args.
05Logic / I/O separation🚀 Ship-Ready
Clean Abstractions/ layer: IInputSource, IOutputTarget, IPdfTextExtractor, IDocumentClassifier — all wired via DI in Program.cs:36-44. DocumentProcessor is testable without filesystem/network — confirmed by tests/PaperClaw.Tests/Processing/DocumentProcessorTests.cs.
06One-command bring-up🩹 Patchy
No README. No Makefile / Justfile / Taskfile. CLAUDE.md only documents Windows-absolute paths through PowerShell. dotnet build / dotnet test at the PaperClaw/ level works against the .sln but is undocumented; agent has to guess. Bonus headache: project is double-nested at PaperClaw/PaperClaw/PaperClaw/.
Fix: add a README.md at the repo root with dotnet restore && dotnet build PaperClaw/PaperClaw.sln && dotnet test PaperClaw/PaperClaw.sln, or flatten the directory layout.
07Pre-commit feedback loop💀 Broken
No lefthook.yml, no .husky/, no .pre-commit-config.yaml, no .githooks/, no core.hooksPath. Nothing fires before commit.
Fix: add lefthook.yml with pre-commit stages running dotnet format --verify-no-changes --include {staged_files}, gitleaks protect --staged, and dotnet test PaperClaw/PaperClaw.sln --no-build.
08Dead-code guardrail💀 Broken
No analyzer flags unused symbols as errors. IDE0051 / IDE0052 / CA1812 default to suggestion, not error. No CI step.
Fix: in .editorconfig: dotnet_diagnostic.IDE0051.severity = error and dotnet_diagnostic.IDE0052.severity = error; couple with <EnforceCodeStyleInBuild>.
09Logs reachable👍 Solid
All status output goes to stdout (Program.cs:47-65). Per-document log.txt is written into each outbox folder (FileOutputTarget.cs:37) — tailable by an agent. No dedicated logs / tail script though.
10Docs stay in sync💀 Broken
paperclaw.md is a static spec — nothing checks that source matches it, nothing flags code-only changes. CLAUDE.md already drifted: it points at a Windows path layout that doesn't exist on most checkouts.
Fix: add a lefthook check that warns when files under PaperClaw/PaperClaw/ change without touching paperclaw.md or CLAUDE.md; or generate the CLI help section of the docs from --help output.
11Agent self-test end-to-end👍 Solid
.claude/commands/paperclaw.md defines a /paperclaw <question> slash command that builds and runs the real binary, returning stdout the agent can read. The search mode lets the agent exercise the full Claude-tool-calling path against the outbox. Caveat: the command is PowerShell-only with hardcoded Windows paths.
12Agentic review panel💀 Broken
No /review command, no REVIEW.md, no panel script, no CI workflow, no tiered review setup. The human is the first reviewer of every diff.
Fix: add .claude/commands/review.md that fans out parallel sub-agents (security, C# best-practices, DRY, maintainability) over the staged diff, plus a REVIEW.md listing what not to flag (theoretical risks, unchanged code).
13Blast-radius friction💀 Broken
No CODEOWNERS, no danger-zone hook, no explicit bypass mechanism. The most blast-radius-y files (the outbox schema in FileOutputTarget.cs that determines on-disk archive layout, the Claude tool definitions in ClaudeSearchService.cs that contract with the search slash command) get the same friction as a typo.
Fix: add a lefthook pre-push stage that prints a checklist when FileOutputTarget.cs or the tool-schema block in ClaudeSearchService.cs are touched, gated by PAPERCLAW_DANGER_OK=1.
14Tooling tuned for the agent🩹 Patchy
Config-missing errors are clear (Program.cs:16-21: "Anthropic:ApiKey not configured"). But: no hooks exist to tune at all, so there's no remediation channel to speak of. No .gitleaksignore, no copy-pasteable "run this to fix" lines anywhere.
Fix: once item 7 is in place, make every hook's failure message print the exact remediation command (e.g. "run dotnet format PaperClaw/PaperClaw.sln" on a format failure).
